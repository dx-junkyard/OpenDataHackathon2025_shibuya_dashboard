# 渋谷区の公開資料から Vision・UX・Feature を導く（ドメイン設定）

**文書の役割:** probe-agent の手法「Vision → UX → Feature の調査手法」を、渋谷共創ダッシュボードに当てはめる設定と実行計画
**手法の正本:** [probe-agent docs/01-specifications/product/vision-to-feature-research.md](https://github.com/dx-junkyard/probe-agent/blob/ura/docs/01-specifications/product/vision-to-feature-research.md)（手順 VF-S0〜S9、区別 VF-D1〜D5、主張の型、現状 C-1〜C-3、仮説構築はそちらが所有する）
**関係する正本:** [Vision](vision.md) → [UX](ux.md) → [Feature](features.md)。この文書はそれらの中身を所有せず、根拠をどう集めて更新するかの渋谷区向けの具体値だけを持つ
**状態:** draft（2026-10-24）。最初の一周の S1〜S8 を実施済み（§8、§9、[ux.md §6](ux.md#6-代表シナリオの現状と目指す体験s5s62026-10-24)、[features.md §8](features.md#8-外遊びの代表シナリオの差と埋め方s7s82026-10-24)）。S9（再評価）は次期長期基本計画の確定時に行う

手法そのもの（何を区別し、どの順で調べ、どう仮説を立てるか）はここに書かない。
ここに書くのは、手法の §7「ドメイン設定」の各項目に対する渋谷区での値である。

まさにこの区別を崩さないための理由である。

## 3. 主張の型の扱い

手法 §3.2 の型をそのまま使い、新しい型は足さない（手法は型の語彙を全プロジェクトで共通に保つ）。
区の 7 つの分野（AREA-1..7）は、基本構想の `aspiration` / `policy_goal` の主張と、Sponsor
`shibuya-city` の Need の対応で表す。

`indicator`（指標・目標値）は、課題カードの KPI 候補（F-07）の根拠としても使う。区の指標を KPI に採るときも、
採るかどうかは当事者が決める（[Vision P-2](vision.md#7-製品原則)）。

## 5. 台帳の場所

```text
docs/sources/
  README.md      台帳（手法 §3.3 の項目）。取得できなかった資料も行を持つ
  <source_id>.md 本文（ページ境界付き Markdown）
  <source_id>-indicators.csv  指標表（必要なとき）
```

`probe-agent.yml` の `repository.include` にある `docs/**` に含まれるので、設定変更は不要。
渋谷区サイトの転載条件を確認できなかったため、最初の一周ではすべて要約と頁参照だけを置いた。

## 6. 最初の調査目的（S0 の初期値）

> 区の公開方針（次期長期基本計画を含む）に照らして、OBJ-1..5 と F-01..22 の優先度が区の目標に沿っているか、
> 寄与先のない区の目標から新しい Objective が必要かを判断する。

対象範囲は、まず代表シナリオの分野（AREA-1 子育て）と、本製品の前提であるデータ活用・DX 分野に絞る。

## 8. 最初の一周の結果（2026-10-24）

| 手順 | 結果 |
| --- | --- |
| S1 | 8 資料を台帳に登録（うち次期長期基本計画の素案は未公表で取得不可）。probe-agent の台帳検査は誤り 0、注意 4（いずれも検討委員会の案であること） |
| S2 | probe-agent が資料から 104 件の主張を資料・頁付きで抽出（政策目標 50、指標 20、問題認識 9、施策 8、目指す姿 7、制約 7、意見 3）。2017-2026 計画の成果指標（待機児童数 315人→0人、合計特殊出生率 1.07→1.46、プレーパーク 1→2）は原文の値と一致。検討委員会の委員の意見 3 件は区の目標と分けて「意見」として抽出 |
| S3 | 区の目標を Stakeholder `shibuya-city` の Need 7 件として登録し、根拠に `source:` 参照を付けた（読み取り時に資料の層・版・期間が結合される） |
| S4 | OBJ-1..5 と区の目標を 10 本の関係で結んだ（[vision.md §5](vision.md#区の目標との対応s42026-10-24)）。製品の目標でない区の目標（外遊び）は課題カードの題材として扱う |

この一周で probe-agent 側に見つかった不足と対応:

- 推論モデルの判定が名前の一覧で、`gpt-6-luna` を推論モデルと認めず主張抽出が止まった → 系列と版で判定するよう修正。
- 委員の意見（「…との意見」）が区の政策目標として抽出された → 資料の中の発行者以外の意見を `opinion` として区別。
  その後、区が数値で報告するアンケートの集計値まで意見になったため、集計値は `indicator` とする規則を加えた。
- 同じ snapshot の再ビルドで、抽出の版が変わっても古い結果を再利用し、読み直した後もグラフを作り直さなかった
  → 版が変わったチャンクだけ読み直し、新しい抽出があればグラフを作り直すよう修正。
- Objective と区の目標の関係を「仮説」として記録する手段がない（人の確定としてしか残せない）→ 未対応。今回は注記で区別した。
- 推論モデルでは出力上限に内部の推論も含まれ、長い節（表）の抽出で答えが空になり理解の更新が止まった
  （2026-10-24、題材変更後の再読み込みで発生）→ 推論モデルの上限を広げ、上限で切れたらそう報告するよう修正。
- Gap の検出元に形式の違う参照（`journey|step` の `|` がない）を渡すと保存され、永久に「消えた」と表示された
  （S7 で発生）→ 作成時に拒否し、期待する形式を返すよう修正。S7 で誤って保存した 4 件は追記専用のため残っている。

## 9. 代表シナリオの変更（2026-10-24）

最初の一周の S4 で、代表シナリオ「授乳・おむつ替えスポット」は読んだ区の資料のどこにも出てこない一方、
区民アンケートで子育て支援の要望の最多が「子どもが自由に安心して外遊びができる環境づくり」（43.9%）だと分かった。
利用者の判断で、代表シナリオを外遊びに変えた。手法の推奨どおり、変える前に外遊びの資料を追加で探した（S1 の追加）。

- 追加した資料: 区の公園一覧オープンデータ（123 件、CC BY）、プレーパークの運営団体の説明、
  次期計画の主要課題まとめの政策 14・15（公園を核とした地域コミュニティ、データダッシュボード活用）。
- 見つからなかった資料: 子ども・子育て支援事業計画、こども計画（Web 検索と区のオープンデータカタログで探した範囲）。
- S5〜S6 の結果は [ux.md §6](ux.md#6-代表シナリオの現状と目指す体験s5s62026-10-24)。
